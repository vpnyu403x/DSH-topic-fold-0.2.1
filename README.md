# 话题折叠（dsh-topic-fold）

把聊天里**每个话题**（你的一次提问 + 它的整段回答）折叠成一行提示词。长会话找东西时，先看一屏问题，再展开要的那一个。

## 安装

**插件 → 添加插件 → 选择本目录**（就是包含 `package.json` 的这一层）。装完刷新/重开页面即可。

## 用法

- **单个话题**：每个提问的**左侧空白处**有一个小圆点箭头（鼠标移上去才明显，圆点直径 24px）。
  - 点一下 → 折叠：只留下你的提问（以及这一轮里的插话），回答、工具调用、过程、用时统计全部收起；箭头变成带边框的圆点，方向朝右。
  - 再点一下 → 展开。
  - 它不额外加高（绝对定位在左侧留白里，只借用提问上方本来就有的约 6px 行间距），展开状态下也几乎不会把会话拉长。
- **全部话题**：会话标题栏右侧多一个胶囊按钮。
  - 「全部折叠」把当前已加载的每个话题都折起来；
  - 全部折好后按钮变成「全部展开」。
  - 折叠后会尽量把你原来正在看的那条提问留在视野里，不会直接跳走。
- **对话空白处右键**：在对话内容的空白区点右键（消息之间的空隙、每条消息内部的留白、内容两侧的留白、最后一条消息下方、输入卡片周围的空带），会弹出只属于本插件的两项菜单：
  - 「全部折叠」/「全部展开」，效果和标题栏按钮一致；
  - 已全折叠时「全部折叠」置灰，没有折叠时「全部展开」置灰，不会出现点了没反应的情况。
  - 在消息文字、代码块、链接、图片、按钮、输入框、已选中的文字、会话标题栏/侧栏上点右键，不会被接管，仍走它们自己的菜单。
  - 判定方式：右键落点只要不落在上面这些“有主”的元素上，就算空白区——不再要求必须落在消息行之外，所以消息行之间的空隙和行内留白都能触发。
- **正在生成的那一轮不能折叠**：箭头会置灰，悬停提示「正在生成，结束后可折叠」，避免把正在刷新的回答藏起来。批量折叠（标题栏按钮和右键菜单）同样会跳过它。

折叠状态按会话记录在浏览器 `localStorage`（键 `dsh.topic-fold.v1`），刷新、重启后仍在；不同会话互不影响。

## 折叠后仍然可见的内容

折叠只隐藏「过程 + 回答」，以下内容保持显示，避免把问题藏起来：

- 你的提问和同一轮里的插话（steering）；
- 命令输入行（例如这一轮的 `/目标`）、以及这一轮的触发来源（定时/事件等）；
- 报错（turn error）、模型重试状态、输出超长（max tokens）提示、未知内容块。

## 和自带「过程折叠」的关系

Chat 原本就会把已完成回合的**过程**折成「已工作 N 分钟」一行，但回答正文始终显示。本插件折叠的是**整个话题**（提问之后的所有内容），两者可以同时用：

- 只想要更短的回合：用自带的「工作细节 / 折叠时机 / 折叠回答」设置。
- 想按话题扫读：用本插件的箭头或标题栏按钮。

## 限制（提前知道）

- 折叠只改**显示**：会话数据、发给模型的内容、导出都完全不变。
- 被隐藏的文字**不会被浏览器「查找」命中**，**也不会被选中复制**；需要先展开。
- 只作用于 **对话（Chat）视图**；轨迹等其他视图不受影响。
- 批量折叠只覆盖**当前已加载**的话题；更早的话题在滚动加载出现后同样可以折叠。
- 没有「自动折叠新话题」；新话题默认展开，折叠状态由你决定。
- 撤销：再点一次「全部展开」即可恢复。
- 极少数没有人类提问的回合（例如只有定时触发）不会进入批量折叠，以免折成一个找不到入口的空回合；纯图片提问没有文字预览，标题栏按钮的统计会略过它，但右键菜单和它自己的箭头仍能正常折叠。
- 右键菜单出现在「对话内容区」的空白处；右侧边栏里的子会话聊天同样可用（折叠状态按那个子会话单独记）。
- 如果同一条提问上方另一个插件（例如 Liveshare 的共享来源标记）先占用了这个插槽，那条提问就没有小箭头；在有标题栏的主对话里，它仍会被「全部折叠」正确折叠。但嵌入式对话（右侧边栏里的子会话，没有标题栏）里，这类提问就没有折叠入口。
- 插件通过读 `data-chat-turn` / `data-chat-flow-kind` / `data-conversation-session` / `data-chat-running` 这几个宿主渲染属性定位并隐藏行、判断是否正在生成；DSH 大版本升级如果改了这些属性，需要同步更新 `client.js` 里的 `hideRule()`、`promptTurnsOf()` 和 `runningIn()`。
- 右键菜单依赖 DSH 自带的共享右键菜单服务（桌面版标准安装都有）。如果右键完全没反应，先在开发者工具控制台看两行日志：`[topic-fold] blank-area menu ready`（监听就绪）和 `[topic-fold] blank-area menu <会话id> <话题数>`（成功接管一次右键）。只有第一行没有第二行，说明那一处确实被判成“有主”的元素了。

## 实现

| 文件 | 作用 |
|---|---|
| `client.js` | 浏览器插件：每个提问左侧的折叠圆点 + 标题栏的批量按钮 + 对话空白处右键菜单 + 每个会话的折叠状态与隐藏规则 |
| `index.js` | Host 侧占位插件行（功能全在前端） |
| `cordis.patch.yml` | 把插件行插进 bundle |
| `locale/*.json` | 插件页里显示的名称与说明 |
| `icon.svg` | 插件图标 |
